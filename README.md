# EarlyTrace

**Synthetic, advisory, pre-authorisation scam-pattern recognition for a bank/PSP fraud analyst.** EarlyTrace scores one payment event at the urgent-new-payee moment, explains why, abstains when it cannot be sure, and records human review decisions on a hash-chained audit trail. **It never moves money.** Every action is advisory and record-only.

Track 2 (AI-driven scam pattern recognition). All data in this repository is **synthetic and generated by us**; results are descriptive, not generalisable. No real UPI/bank/NPCI data, no calibrated probabilities, no neural/GNN/TGN model, no production or DPDP-compliance claim.

> **Live sandbox demo:** https://earlytrace-demo-749096933589.asia-south1.run.app
> One-click sandbox login, shared synthetic tenant, scale-to-zero. Visitors need no key.

---

## What it is

A customer is socially engineered into paying a new beneficiary, and the funds move onward before a complaint exists. An analyst needs a bounded, explainable reason to verify or review while it is still a question, not a verdict. EarlyTrace is the explainable, abstaining **pre-authorisation decision and review layer** that:

- scores a minimised, server-signed synthetic payment event with event-time-safe motif features;
- returns an advisory action (`ALLOW`, `WARN_AND_VERIFY`, `STEP_UP`, `ANALYST_REVIEW`) or `UNKNOWN` (abstention) with reasons and an uncertainty label;
- gives an analyst a tenant-scoped queue, an evidence graph, an event-time timeline, and record-only receipts;
- writes a hash-chained PAUD audit entry for every decision and review.

Scores are **uncalibrated risk indices**, not probabilities. The system **cannot** freeze, reject, reverse, hold, accuse, or file a report.

### Where EarlyTrace sits (designed to consume, not replace)

| Existing India system | What it does | What EarlyTrace adds |
|---|---|---|
| RBIH MuleHunter | Account-level mule classification inside the bank, batched (T+1 / hourly / near-real-time) | A per-event decision at the moment of authorization |
| DoT FRI | Mobile-number risk tier (Medium / High / Very High) | An explainable per-payment decision with abstention |
| RBI DPIP | National intelligence-sharing platform | A review and decision layer designed to consume shared signals |

EarlyTrace is **designed to consume** these signals. It is **not integrated** with any of them.

## Architecture (summary)

```
institution event -> server-signed/attested envelope -> consent + history context
  -> B0/B1 scorer -> RiskDecision (action, uncertainty, reasons)
  -> analyst workspace -> record-only receipt -> hash-chained PAUD audit
```

- **Server-owned trust boundary.** The HTTP request is an identifier/digest envelope only. Semantic fields, history, `as_of`, hub state, and participation cannot arrive on the request; the server resolves a registered event and checks its digest before scoring.
- **Never collected:** OTP/PIN/MPIN, exact amounts, phone/email/VPA, raw account/reference, device fingerprints, IP, audio, SMS/WhatsApp, contacts.
- **UNKNOWN** on missing/expired/revoked/conflicting consent, stale/future events, insufficient evidence, or unusable calibration. UNKNOWN never invents a score.
- **Tenant isolation**, RBAC, SQLite decision ledger with idempotency and crash recovery, hash-chained audit verified on boot.

## What we do not claim / limits

- Synthetic data we generated — results are **descriptive, not generalisable**.
- No calibration; scores are uncalibrated risk indices.
- B1 misses ~38% of positive stories; a hub outage degrades it to ~46% story recall.
- No real bank/NPCI/UPI integration; single-node SQLite storage; no load test; no user study.
- The `production` profile intentionally refuses to start.
- Tokens are pseudonymous, not anonymous if linked outside this system.
- External dataset rights (e.g. IEEE-CIS, Elliptic) remain unresolved; no Kaggle upload or token join is performed.
